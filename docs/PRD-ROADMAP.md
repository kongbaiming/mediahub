## 1. 产品定位

**一句话**：在家庭 NAS 上运行的自建媒资中心——从下载、刮削、布局运营到 Web / TV 播放，数据与体验完全自主可控。

**对标体验**：家庭内网的「可配置 Netflix」——CMS 拖拽首页、猜你喜欢、续播、儿童过滤，4K 内网优先原画质。

**部署假设**：家庭内网（如群晖 DS920+），不面向公网多租户；默认 admin 改密即可，账号体系暂缓（见 [§10](#10-暂缓不做)）。

## 2. 目标用户与核心场景

| 用户 | 典型场景 | 成功标准 |
|------|----------|----------|
| 家庭管理员 | 配置下载、刮削、首页布局 | 新剧集自动有海报、首页与 CMS 一致 |
| 家庭成员（Web） | 浏览器看剧、续播、猜你喜欢 | 点进即播、4K 不糊、加载可接受 |
| 家庭成员（TV） | 索尼 Android TV 大屏 | Feed 与 Web 一致、遥控器友好 |
| 管理员（运维） | Docker 部署、CI、升级 | 一键 compose、CI 绿、CHANGELOG 清晰 |

**主路径（Happy Path）**：

```
qBittorrent 下载完成 → 扫描入库 → TMDB 刮削 → CMS 布局发布
    → Web/TV Feed 展示 → 选集播放 → 续播 / 推荐下一部
```

### 3.2 播放策略（DS920+ 约束下的产品决策）

内网 4K 是**硬需求**，J4125 **不能依赖软转 4K**。播放优先级：

```
1. 直连（MP4/H.264、客户端可硬解的格式）
      ↓ 失败或不支持（如 MKV + HEVC）
2. HLS 流复制（-c:v copy，保持原 4K，CPU 极低）  ← v0.4 默认路径
      ↓ 流复制失败
3. HLS 转码（可配 1080p / 720p / 480p，QSV 硬转）
```

| 配置项 | 含义 | 推荐（内网 4K） |
|--------|------|-----------------|
| `TRANSCODE_PREFER_COPY` | MKV HEVC 等走流复制 | `true` |
| `TRANSCODE_MAX_HEIGHT` | 必须转码时的上限；`0` = 源分辨率 | 按需，默认 `480` |
| `TRANSCODE_MAX_BITRATE` | 转码码率 | 转码时 `8000k`+ |

## 8. 明确不做（当前阶段）

| 项 | 原因 |
|----|------|
| 公网多租户 SaaS | 定位家庭自建 |
| 内置 tracker / 盗版索引 | 合规 |
| 替代 Jellyfin 全协议（DLNA 等） | 范围控制 |
| 手机原生 App | Web + TV 优先 |
| 完整账号 / OAuth / 2FA | 见 §10 |

---

## 9. 优先级原则

1. **体验闭环优先** — 刮削、播放、布局三者一致，再堆功能  
2. **内网 4K 可用** — 流复制 > 直连 > 转码，不默认 480p 糊片  
3. **多端对齐** — Web 验证后再推 Android TV，Feed 契约统一  
4. **小步发布** — minor 版本可部署、CHANGELOG 可追踪  
5. **账号安全** — 有公网或多家庭需求再开（§10）  

---

## 10. 暂缓不做

以下**移出 v0.4–v1.0**，待产品有公网暴露或多家庭共享需求时再评估：

| 原需求 | 当前替代 |
|--------|----------|
| 多用户 / 家庭账号 | 单 admin + 多 Profile（localStorage） |
| TV 设备长期 Token | Setup 填 API URL |
| 儿童 PIN 后端校验 | 前端 PIN 提示 |
| Profile 全量后端化 | `X-Profile-ID` + 默认 Profile API |
| API Rate Limit / WAF | 内网部署指南 |
| 审计日志 | — |
| OAuth / 2FA | — |

**安全基线**：改默认密码；不对公网暴露 Admin/API；必要时反向代理 + 自签证书。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| TMDB 限流 / 不稳定 | 刮削 pending 堆积 | 重试、超时、可选镜像 |
| J4125 软转 4K | CPU 100%、卡顿 | **流复制**、QSV、降档可配 |
| Docker fsnotify 漏事件 | 新文件未入库 | 定时 scan + 手动 `/scanner/scan` |
| HLS 缓存膨胀 | 磁盘占满 | v1.0 LRU；v0.4 文档说明清理 |
| 单人维护 | 迭代慢 | 严格 P0/P1，版本小步发 |
| 旧方案文档过时 | 误导开发 | 以本文档为准；旧文档标注归档 |

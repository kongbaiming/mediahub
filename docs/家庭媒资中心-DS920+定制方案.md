# 家庭媒资中心 - DS920+ 定制方案

> 基于 **群晖 DS920+** (Intel J4125) + **索尼 Android TV** + **Apple TV** 的硬件定制版本。
> 多账号低优先级，布局进阶版（模板 / AB / 动态）。

---

## 0. 硬件评估（DS920+）

| 组件 | 规格 | 对媒资中心的影响 |
|---|---|---|
| CPU | Intel Celeron **J4125**（4 核 2.0GHz / boost 2.7GHz） | 软转 4K 吃力，1080p 软转没问题 |
| GPU | Intel UHD 600（Quick Sync Gen9.5） | **HEVC/H.264 硬解 OK，硬转能力有限** |
| RAM | 默认 4GB DDR4（可扩 8GB） | **建议扩到 8GB**：Jellyfin 缓存 + 转码 + 容器都吃内存 |
| 盘位 | 4 盘位 | RAID5 标配；推荐 SSD 缓存盘提升小文件读取 |
| 网口 | 2× 1GbE（可链路聚合） | **单口就够 4K 直连**，链路聚合上限 2GbE |

### 转码策略（关键！）

```
优先级 1：内网直连 NAS 原文件（SMB/NFS）→ 客户端硬解
   ↓ 客户端硬解失败（格式不支持 / 弱网）
优先级 2：HLS 转码流（Quick Sync 硬转，720p/1080p）
   ↓ 转码也扛不住
优先级 3：原始文件直推（不转码，赌客户端能播）
```

> **不要**指望 J4125 软转 4K HDR —— 帧率直接腰斩。Apple TV 和索尼电视硬解能力都很强，直连永远是首选。

### 推荐扩容

1. **RAM 升级到 8GB**：单条 DDR4 8GB 笔记本内存，~¥150
2. **M.2 NVMe 缓存盘**：2 条（只读 + 读写缓存），提升元数据/海报读取
3. **存储盘**：4 块 8TB+（如希捷酷狼），RAID5 ≈ 24TB 可用

## 2. 多端策略（索尼 TV + Apple TV 优先）

### 2.1 三个播放端的优先级

| 端 | 优先级 | 框架 | 工期 | 备注 |
|---|---|---|---|---|
| **Web Player** | P0（必须） | Vue 3 + hls.js | 5-7 天 | 覆盖电脑 + 投屏 + 平板 |
| **Android TV**（索尼） | P0（必须） | Kotlin + Leanback + ExoPlayer | 10-15 天 | 家里主力电视 |
| **tvOS**（Apple TV） | P0（必须） | SwiftUI + AVPlayer | 15-20 天 | 国内 App Store 上架另议 |

### 2.2 关于 Apple TV 的部署方式 ✅ 已确认 TestFlight

#### TestFlight 的硬约束（务必先了解）

| 约束 | 说明 |
|---|---|
| **build 有效期** | 每个版本 90 天，到期需重新构建上传（自己用影响小，每月构建一次即可） |
| **外部测试者上限** | 10000 人，家庭场景绝对够 |
| **账号要求** | Apple Developer Program **$99/年**（个人或组织） |
| **国行兼容性** | ✅ 完全可用，TestFlight 不受 App Store 地区限制 |
| **构建环境** | ⚠️ **必须在 macOS + Xcode 构建**，Windows 上无法直接出 .ipa |
| **审核要求** | 首次外部测试需要简单审核（1-2 天），后续 build 无审核 |

#### 构建方案（Windows 开发者的核心痛点）

你的工作环境是 Windows，tvOS 必须 macOS 构建，三条路：

| 方案 | 成本 | 难度 | 推荐度 |
|---|---|---|---|
| **A. 云 CI 构建（Codemagic）** | 免费 500 分钟/月 | ⭐⭐ | ⭐⭐⭐⭐⭐ **首推** |
| B. 自购 Mac mini | ¥4000+ | ⭐⭐⭐ | ⭐⭐⭐ |
| C. 朋友/外包帮忙构建 | 人情/费用 | ⭐ | ⭐⭐ |

**推荐 Codemagic 流程**：

```
GitHub push → Codemagic 触发 → macOS runner 跑 Xcode 构建
   → 自动签名（管理证书）
   → 自动上传到 App Store Connect
   → TestFlight 内部测试组立即可用
```

配置文件 `codemagic.yaml`：

```yaml
workflows:
  tvos-build:
    name: tvOS Build
    environment:
      flutter: false
      xcode: latest
    scripts:
      - name: Install deps
        script: |
          cd tvos
          pod install
      - name: Build & sign
        script: |
          xcodebuild -workspace MediaHubTV.xcworkspace \
            -scheme MediaHubTV \
            -configuration Release \
            -sdk appletvos \
            -archivePath build/MediaHubTV.xcarchive \
            archive
          xcodebuild -exportArchive \
            -archivePath build/MediaHubTV.xcarchive \
            -exportPath build/output \
            -exportOptionsPlist exportOptions.plist
    publishing:
      app_store_connect:
        auth: integration
        submit_to_testflight: true
```

> **Windows 写 Swift 代码 → push GitHub → Codemagic 自动构建 → TestFlight 收到通知 → Apple TV 装上**。这就是最现实的开发节奏。

#### 自动续命策略

90 天有效期容易忘，建议加个 GitHub Action 定时任务：

```yaml
# .github/workflows/refresh-tvos.yml
on:
  schedule:
    - cron: '0 0 1 */2 *'  # 每两个月第一天提醒
jobs:
  remind:
    runs-on: ubuntu-latest
    steps:
      - name: 提醒重建
        run: echo "::warning::tvOS build 即将过期，请 push 触发 Codemagic 重建"
```

或者用 Codemagic 的 monthly build 计划，每月自动重建一次。

### 2.3 三个端的共用逻辑

布局 JSON 协议是统一的，三个端只换渲染层：

```
[布局 JSON] → [端侧渲染器] → [用户界面]
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
    Web (Vue)  Android TV  tvOS (SwiftUI)
                (Kotlin)
```

建议共享：
- 布局数据模型（TypeScript / Swift / Kotlin 三份）
- 数据请求 API（REST/GraphQL）
- 焦点导航逻辑（远控键盘的上下左右 → 卡片焦点）

## 3. 进阶布局编辑器（重点）

### 3.1 进阶功能矩阵

| 功能 | 说明 | 价值 |
|---|---|---|
| **模板继承** | 基础模板 → 派生「家庭模板」「儿童模板」 | 一套底层，多场景复用 |
| **多版本管理** | 草稿 / 预览 / 发布 / 历史 | 改了不怕炸 |
| **多端差异化** | 同一份数据，Web/Android TV/tvOS 三套布局 | 发挥各端优势 |
| **AB 测试** | 同时发布两个布局，统计点击率 | 找出最优组合 |
| **动态布局** | 时段（白天/夜晚）、星期、季节动态切换 | 春节推贺岁片 |
| **数据源编排** | 多数据源 + 过滤 + 排序 + 限制 | 灵活组合 |
| **预览模式** | 720p / 1080p / 4K 模拟预览 | 真实感 |

### 3.2 数据源类型（进阶版）

```typescript
type DataSource =
  | { type: 'manual', ids: string[] }                  // 手动选片
  | { type: 'library', filter: FilterExpr, sort: SortRule, limit: number }
  | { type: 'tag', tag: string, sort: 'rating' | 'year' | 'added' }
  | { type: 'trending', source: 'tmdb' | 'douban', period: 'day' | 'week' }
  | { type: 'similar-to', mediaId: string, by: 'tag' | 'director' | 'cast' }
  | { type: 'continue-watching', userId?: string }
  | { type: 'recently-added', days: number }
  | { type: 'recommend-algorithm', algo: 'cf' | 'content' | 'hybrid' }
  | { type: 'union', sources: DataSource[], dedup: boolean }   // 合并
  | { type: 'exclude', source: DataSource, exclude: string[] } // 排除
```

### 3.3 模板继承示意

```
BaseTemplate (基础模板)
├── rows: [Hero, Continue, Recent, TopRated]
│
├── FamilyTemplate extends BaseTemplate
│   └── adds: [KidsShelf, Documentary]
│   └── overrides: Hero (换成春节专题)
│
└── SoloTemplate extends BaseTemplate
    └── removes: KidsShelf
    └── adds: [Watchlist, RecentlyLiked]
```

存储结构：

```sql
layouts (id, parent_id, name, version, is_template, ...)
```

### 3.4 布局发布与 AB

```sql
layout_publications (
  id, layout_id, version,
  target_platform ('web' | 'android-tv' | 'tvos'),
  traffic_split (JSON),  -- AB 测试权重
  active_from, active_to,
  enabled
)
```

API：

```
GET /api/v1/feed/:platform?user_id=xxx
  → 根据用户 hash 选 AB 版本
  → 返回合并后的布局 + 行数据
```

## 4. 多账号（简化版）

按你要求低优先级，做**单家庭账号 + 多 Profile** 的折中：

| 维度 | 方案 |
|---|---|
| 登录 | 单家庭账号（一个用户名密码） |
| Profile | 家庭成员每人一个 Profile（老婆/老公/孩子/老人） |
| 共享 | 媒资库、收藏、布局全局共享 |
| 独立 | 播放历史、续播进度、推荐独立 |
| 家长模式 | Profile 标记 `is_kid=true` 时过滤 PG-13 以上 |

> 实现成本极低：表里加个 `profile_id`，筛选时多带个条件。

## 6. 立即可启动的 MVP（W1）

```yaml
# docker-compose.yml (DS920+ 优化)
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: mediahub
      POSTGRES_USER: mediahub
      POSTGRES_PASSWORD: ${DB_PASS}
    volumes:
      - /volume1/docker/mediahub/postgres:/var/lib/postgresql/data
    ports: ["5432:5432"]

  redis:
    image: redis:7-alpine
    volumes:
      - /volume1/docker/mediahub/redis:/data
    ports: ["6379:6379"]

  mediahub-api:
    build: ./services/api
    depends_on: [postgres, redis]
    environment:
      DATABASE_URL: postgres://mediahub:${DB_PASS}@postgres/mediahub
      REDIS_URL: redis://redis:6379
      MEDIA_ROOT: /media
    volumes:
      - /volume1/media:/media   # 媒资目录
    ports: ["3000:3000"]

  mediahub-admin:
    build: ./services/admin
    ports: ["8080:80"]

  media-engine:
    build: ./services/media-engine
    volumes:
      - /volume1/media:/media
    depends_on: [mediahub-api]

  qbittorrent:
    image: linuxserver/qbittorrent
    volumes:
      - /volume1/downloads:/downloads
    ports: ["8081:8080"]
```

W1 完成时你能：
- 浏览器打开 CMS 后台（电脑）
- 看到 NAS 上已有视频被自动扫描入库
- 看到海报、简介、评分（来自 TMDB）
- 手动调整元数据
- Web Player 播放一个视频（直连或转码）

## 8. 风险点（DS920+ 特定）

| 风险 | 影响 | 缓解 |
|---|---|---|
| J4125 软转 4K 吃力 | 4K 转码卡顿 | **直连优先**，只在弱网兜底转码 |
| 4GB RAM 偏紧 | Docker 多服务时 OOM | **扩 8GB**（强烈建议开工前先扩） |
| 4K HDR 文件大 | 千兆网口吞吐刚好够 | 大文件用 SMB 直连；播放端做缓冲 |
| 容器磁盘 IO | 媒体扫描慢 | 媒资库放机械盘，Docker 数据放 SSD |
| 索引源敏感 | 需要稳定 BT/PT 源 | Downloader 设计成可热插拔源 |

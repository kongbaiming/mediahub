# 家庭媒资中心方案

> 目标：把家里散落在 NAS 上的影视资源统一管理起来，配上自动下载、智能推荐，并在电视、电脑、Apple TV 上都能流畅观看。

---

### 三个角色各管一段

| 角色 | 干啥 | 跑在哪 |
|---|---|---|
| **下载器** | 自动追剧、抢种、做种 | NAS 容器或群晖 Download Station |
| **媒资 CMS**（自建） | 元数据、分类、评分、推荐、播放历史 | NAS 容器或独立小主机 |
| **媒体服务器** | 真实转码 + 流媒体分发 | Jellyfin，NAS 容器 |

> 关键点：CMS 负责「管」和「推荐」，Jellyfin 负责「播」。两边通过 API + 文件路径联动，避免重复造播放器。

## 2. 核心模块设计

### 2.1 下载管理

**推荐方案：qBittorrent + Sonarr（剧集）+ Radarr（电影）+ Prowlarr（索引）**

- Sonarr / Radarr：追新剧、追新电影，自动改名、整理、移到对应文件夹
- Prowlarr：聚合索引站（PT、BT、公开站），统一喂给 Sonarr/Radarr
- qBittorrent：下载客户端，比群晖原生 Download Station 自动化更好

> 也可以保留群晖 Download Station 做兜底，把 Sonarr/Radarr 的下载器指向它。

### 2.2 媒资存储结构

```
/volume1/media/
├── movies/              # 电影
│   └── 星际穿越 (2014)/
│       └── 星际穿越.mkv
├── tvshows/             # 剧集
│   └── 浴血黑帮/
│       └── Season 06/
│           └── S06E01.mkv
├── anime/               # 动画
└── documentaries/       # 纪录片
```

命名规范用 Sonarr/Radarr 的标准格式，CMS 端就不用猜了。

### 2.3 媒资 CMS 后台（自建）

功能清单：

| 模块 | 功能 |
|---|---|
| **元数据** | 刮削 TMDB（首选）+ 豆瓣（兜底中文），海报、简介、演员、剧照 |
| **分类** | 电影 / 剧集 / 动画 / 纪录片；按类型、地区、年份、评分筛选 |
| **推荐** | ① 热门榜单（TMDB trending） ② 「猜你喜欢」（基于观看历史 + 标签相似度） ③ 编辑精选 |
| **收藏** | 想看 / 在看 / 看过 / 评分 |
| **播放历史** | 多端同步进度，跨设备续播 |
| **用户管理** | 家庭成员多账号 + 观影权限（家长模式） |
| **播放入口** | 一键跳到 Jellyfin 播放（或直接走 HLS 直连） |

### 2.4 播放端

| 设备 | 推荐客户端 | 备选 |
|---|---|---|
| 电脑 | Jellyfin Web / Plex Web | VLC、IINA、PotPlayer（直连 NAS） |
| 智能电视 / Android TV | Jellyfin TV 客户端 / Kodi | 装 VLC、MX Player |
| Apple TV | **Infuse**（强烈推荐，付费 ~¥60 一次性） | Plex 客户端、CloudStream（国行可用） |
| iPhone / iPad | Infuse / Jellyfin 官方 | VLC |

> **Apple TV 国行注意**：App Store 里没有 Plex/Jellyfin 官方客户端，但 Infuse 一直在；Infuse 可以直接对接 Jellyfin/Plex 服务，体验最好。

## 3. 技术选型（自建 CMS 部分）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Node.js (NestJS)** 或 **Python (FastAPI)** | 生态成熟，方便做爬虫和异步任务 |
| 前端 CMS | **Vue 3 + Element Plus** 或 **React + Ant Design** | 后台类项目主流 |
| 数据库 | **PostgreSQL** | 需要全文检索、复杂查询 |
| 任务队列 | **BullMQ / Celery** | 跑刮削、生成缩略图等异步任务 |
| 元数据 | **TMDB API**（首选）、**豆瓣**（中文元数据补充） | TMDB 最全，豆瓣补剧情简介 |
| 媒体服务器 | **Jellyfin**（开源免费） | 自带转码、Web 端、多端客户端齐全 |
| 部署 | Docker Compose（NAS 上） | 一键起一组服务 |

### 推荐项目骨架

```
mediahub/
├── docker-compose.yml          # 一键起所有服务
├── nas/                        # NAS 路径映射
│   └── media/
├── services/

│   ├── cms-web/                # 后台前端
│   ├── jellyfin/               # 媒体服务器
│   ├── sonarr/                 # 剧集自动管理

│   ├── prowlarr/               # 索引聚合
│   └── qbittorrent/            # 下载客户端
└── docs/
```

## 4. 落地步骤（按依赖顺序）

### 第一阶段：基础设施（1~2 天）
1. 群晖安装 Docker（套件中心）
2. 用 Docker Compose 起 Jellyfin + qBittorrent，验证能播放本地视频
3. 配置 NAS 文件夹权限和共享

### 第二阶段：自动下载（2~3 天）
1. 部署 Sonarr + Radarr + Prowlarr
2. 接入 PT 站或公开 BT 源
3. 配置「想要 → 自动下载 → 自动改名 → 自动入库」全流程

### 第三阶段：CMS 后台 MVP（5~7 天）
1. 搭后端框架 + 数据库
2. 实现 TMDB 刮削（电影 / 剧集）
3. 简单 Web 后台：列表、详情、搜索、筛选
4. 与 Jellyfin 联动：CMS 里点「播放」跳转 Jellyfin

### 第四阶段：推荐 + 多端（3~5 天）
1. 接入观看历史（从 Jellyfin API 拉）
2. 简单推荐：标签相似度 + 热门榜单
3. 电视端装 Jellyfin TV，Apple TV 装 Infuse，电脑直接用 Web

### 第五阶段：打磨（持续）
- 转码性能调优（NAS CPU 弱就开硬件转码）
- 字幕自动下载（bazarr）
- 海报墙、刮削修正工具
- 备份策略（重要！）

## 5. 工作量与成本预估

| 项 | 自建工作量 | 现成方案 |
|---|---|---|
| 下载自动化 | 1~2 天 | 直接用 Sonarr/Radarr |
| CMS 后台 | 7~15 天 | 可以不做，用 Jellyfin 自带库 |
| 媒体服务器 | 几乎为 0 | Jellyfin 开箱即用 |
| 播放端 | 几乎为 0 | Infuse + Jellyfin TV |
| **合计** | **10~20 天**（单人周末节奏） | 纯 Jellyfin + Sonarr/Radarr 当晚就能用 |

### 关键决策：你需要的是哪种方案？

- **轻量派（推荐先用这套）**：Jellyfin + Sonarr/Radarr + Infuse，先把下载和播放跑起来。CMS 只在需要时再加。
- **进阶派**：在轻量派基础上加自建 CMS，主要为了「推荐」「收藏」「观影记录」这些 Jellyfin 偏弱的能力。
- **重量派**：完全自建，包括播放端 SDK。除非有非常个性化的需求（比如要和家庭智能联动），一般不建议。

## 6. 推荐优先级

如果只能选三件事先做：

1. **Jellyfin + Infuse** —— 当晚就能在电视、Apple TV 上看 NAS 里的片，体验质变
2. **Sonarr + Radarr** —— 再也不用手动追剧
3. **自建 CMS 推荐层** —— 在 1、2 的基础上做差异化

> 经验之谈：很多人一上来就堆功能，结果下载了一堆但没时间看。先把「流畅播放」跑通，再考虑推荐和管理。

## 7. 待确认的几个问题

为了把方案细化到可执行版本，需要你确认：

1. **NAS 型号和 CPU**：影响硬件转码能不能开（比如 J4125 之后的才比较舒服）
2. **Apple TV 是国行还是海外版**：影响客户端选择
3. **「推荐」具体想要什么**：基于已有片库的相似推荐，还是想接外部榜单（豆瓣 / TMDB trending）
4. **多用户 / 家长模式**：几个人用，要不要分级
5. **PT 站**：有没有已用的 PT 源，决定索引聚合怎么配
6. **CMS 是要自建还是先用现成的**：自建的话要不要我直接帮你起项目骨架

确认完这几点，我可以直接帮你把 Docker Compose 和 CMS 后端骨架搭出来。

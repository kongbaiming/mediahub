# 家庭媒资中心 - 全自建完整方案

> 设计目标：从下载到播放端完全自建。CMS 后台支持可视化编辑 OTT 风格的播放端布局（横滑海报墙、推荐 Banner、专题合集），所有终端（Web / Android TV / tvOS）共用同一套布局配置。

---

## 1. 核心设计理念

### 1.1 灵感来源
参考 Netflix / Disney+ / Apple TV+ / 爱奇艺 TV 端的 UI 范式：

```
┌─────────────────────────────────────────────────────────────┐
│  [ 大 Banner 区：正在热映 / 编辑推荐 ]                          │
│  ─────────────────────────────────────────────────────────── │
│  继续观看 ▶▶  ▶ ▶  ▶                                         │
│  最近添加                                                      │
│  编辑精选 - 诺兰合集                                           │
│  高分经典                                                      │
│  同类推荐：因为你喜欢《盗梦空间》                                │
│  4K HDR 专享                                                   │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 关键抽象：**布局即数据**

播放端不写死结构，而是**从 CMS 拉一份布局描述（JSON）渲染**：

```json
{
  "version": "2026-06-20",
  "theme": "dark",
  "rows": [
    {
      "id": "row-hero",
      "type": "hero-banner",
      "title": "编辑推荐",
      "source": { "type": "manual", "ids": ["tt0816692", "tt1375666"] }
    },
    {
      "id": "row-continue",
      "type": "shelf",
      "title": "继续观看",
      "cardStyle": "landscape",
      "source": { "type": "user-history", "filter": "in-progress" }
    },
    {
      "id": "row-new",
      "type": "shelf",
      "title": "最近添加",
      "cardStyle": "poster",
      "source": { "type": "library", "sort": "added-desc", "limit": 20 }
    }
  ]
}
```

> 这就是 CMS 后台要编辑的东西，也是播放端渲染的依据。

## 3. 模块详细设计

### 3.1 Downloader（下载管理）

**核心功能**：
- RSS / 关键字订阅（如「诺兰」「科幻」自动追新）
- 定时任务（每小时扫描索引源）
- 协议支持：BT、HTTP、磁链
- 文件入库：按 `movies / tvshows / anime / docs` 自动归类
- 命名规范化：`{title} ({year})/{title}.mkv`

**技术实现**：
- 下载核心：集成 `qbittorrent-nox`（容器化）或调用 `transmission-daemon` HTTP API
- 不建议自研 BT 协议（坑极深），但调度、入库、命名可以自建
- 推荐：`backend → qBittorrent API`，自建只做"调度层"

### 3.2 Media Engine（媒体引擎）

**核心功能**：
- 扫描 `/volume1/media/` 增量入库
- 调 TMDB API 刮削元数据（电影/剧集/季/集）
- 兜底豆瓣（中文简介）
- 生成缩略图、海报、剧照（FFmpeg）
- 字幕自动下载（subhd / shooter / opensubtitles）
- 视频指纹（防重复入库）

**技术实现**：
- FFmpeg：转码（h264/h265）+ 切片（HLS）+ 截图
- 文件监听：`inotify`（Linux）/ `FileSystemWatcher`（如跑 Windows）
- 队列：BullMQ / Celery
- **直连优先**：内网直接走 SMB/NFS URL，弱网才走 HLS 转码流

### 3.3 CMS Backend（核心 API）

**REST API 设计**（精简版）：

```
媒资相关
  GET    /api/v1/media?type=movie&sort=year&page=1
  GET    /api/v1/media/:id
  POST   /api/v1/media              # 手动添加
  PATCH  /api/v1/media/:id          # 编辑元数据
  DELETE /api/v1/media/:id
  POST   /api/v1/media/:id/rescan  # 重刮

布局配置（核心）
  GET    /api/v1/layouts                      # 列出所有布局
  GET    /api/v1/layouts/:id                   # 单个布局
  POST   /api/v1/layouts                       # 新建
  PATCH  /api/v1/layouts/:id                   # 更新
  POST   /api/v1/layouts/:id/publish           # 发布版本

播放端拉取
  GET    /api/v1/feed/:layoutId                # 拉取已发布的布局 + 数据
  GET    /api/v1/feed/:layoutId/row/:rowId    # 单行数据（懒加载）

用户
  POST   /api/v1/auth/login
  GET    /api/v1/me
  GET    /api/v1/me/history
  POST   /api/v1/me/favorites

推荐
  GET    /api/v1/recommend/hot
  GET    /api/v1/recommend/similar/:mediaId
```

**数据模型**（精简）：

```sql
-- 媒资主表
media (
  id, type, title, original_title, year, runtime,
  overview, poster_url, backdrop_url, rating,
  tmdb_id, douban_id, genres[], tags[],
  storage_path, file_size, video_codec, audio_codec,
  has_subtitle, created_at, updated_at
)

-- 季/集
seasons (id, media_id, season_number)
episodes (id, season_id, episode_number, title, duration, file_path)

-- 布局
layouts (id, name, target_platform, version, status, created_at, published_at)
layout_rows (id, layout_id, position, type, title, card_style, source_json)

-- 用户
users (id, username, password_hash, role, avatar, created_at)
favorites (user_id, media_id, type, created_at)
history (id, user_id, media_id, episode_id, progress, duration, updated_at)

-- 推荐
recommendations (id, user_id, media_id, score, reason)
```

### 3.4 CMS Admin（管理后台 + 布局编辑器）⭐ 核心亮点

#### 布局编辑器功能清单

**A. 画布区（左侧：模拟电视预览）**
- 16:9 电视框模拟，720p 缩放预览
- 实时同步编辑结果
- 横滑 / 滚动模拟

**B. 组件面板（中间）**
可拖入的组件类型：

| 组件 | 说明 | 关键配置 |
|---|---|---|
| `hero-banner` | 大轮播 | 手动选片 / 自动热门 Top N；自动播放 / 手动 |
| `shelf-poster` | 横滑海报墙 | 卡片大小（poster/landscape/square）、数据源 |
| `shelf-landscape` | 横滑横版海报 | 同上 |
| `category-grid` | 分类网格 | 分类入口卡片 |
| `topic` | 专题 | 专题名 + 手动选片 + 封面 |
| `text-banner` | 文字条 | 公告、专题说明 |
| `divider` | 分隔 | 留白 |

**C. 数据源配置（右侧）**

每行可配置数据源：

- **手动选片**：多选媒资，按拖入顺序排序
- **库筛选**：按类型/标签/年份/评分，组合条件
- **继续观看**：拉用户未看完的
- **同类推荐**：基于"因为你看过 X"
- **热门榜单**：TMDB trending / 豆瓣 top250
- **最近添加**：按入库时间倒序
- **未看清单**：用户收藏了但没看的

**D. 模板与版本**
- 支持保存为模板（"标准模板 / 家庭模板 / 儿童模板"）
- 布局有版本历史，可回滚
- 多端差异化：Web、Android TV、tvOS 可发布不同版本（同一份数据，不同组件配置）

#### 技术实现

- **框架**：Vue 3 + TypeScript + Vite
- **UI 库**：Element Plus + **dnd-kit**（拖拽）
- **状态管理**：Pinia
- **预览画布**：用真实组件 + CSS transform 缩放，模拟电视分辨率
- **关键技巧**：布局 = JSON，编辑器只生成/编辑 JSON，播放端只消费 JSON

### 3.5 播放端（Web / Android TV / tvOS）

#### Web Player（电脑）

- 技术：Vue 3 SPA（与 CMS Admin 共享组件库）
- 视频：`hls.js`（HLS 流）或 `video.js`
- 布局：拉 `/api/v1/feed/:layoutId`，按 JSON 渲染
- 快捷键：空格、左右、F 全屏

#### Android TV Player（电视）

- 技术：**Kotlin + Leanback Library**（官方 TV 框架）
- 或：React Native TV（跨平台折中）
- D-pad 焦点系统（遥控器适配）
- 4K HDR 输出
- 视频：`ExoPlayer`（HLS / DASH）
- 复用 Web 端布局 JSON（但渲染层用原生）

#### tvOS Player（Apple TV）⭐ 最难

- 技术：**SwiftUI + TVMLKit** 或纯 SwiftUI
- 国行 Apple TV：Jellyfin / Plex 客户端不可用，需要自建
- 焦点系统（`@FocusState`）+ 视差海报（tvOS 招牌效果）
- 视频：`AVPlayer`（HLS / 直接播放 mp4/mkv 通过 SMB URL）
- 启动：把布局 JSON 缓存到本地，弱网也能进首页

**关键简化**：三个播放端**布局逻辑共用**，只换渲染层。建议：
- **第一阶段**：只做 Web Player，覆盖电脑 + iPad + 浏览器投屏
- **第二阶段**：Android TV（家里主力电视如果是 Android TV）
- **第三阶段**：tvOS（最后攻坚）

## 4. 推荐引擎设计

轻量级，够用就行：

### 4.1 候选生成
- **热度榜**：TMDB `trending/all/week`
- **同类推荐**：基于"共同喜欢" —— 用户 A 看过 X、Y、Z，找同时看过 X、Y、Z 的人也看过什么
- **协同过滤**：最简单的 user-item 矩阵
- **内容相似**：基于标签/类型/导演/演员的余弦相似度

### 4.2 排序
- 简单加权：`score = 0.5*similarity + 0.3*rating + 0.2*recency`
- 去重：去掉用户已经看过的

### 4.3 推荐位
- CMS 布局里显式声明「同类推荐」「编辑推荐」数据源
- 后端 `/api/v1/recommend/*` 实时计算

## 5. 部署架构（Docker Compose）

```yaml
# docker-compose.yml 概览
services:
  postgres:        # 主库
  redis:           # 缓存 + 队列
  
  mediahub-api:    # CMS Backend
    image: mediahub-api:latest
    depends_on: [postgres, redis]
  
  mediahub-admin:  # CMS Admin 前端 (nginx)
  
  mediahub-web:    # Web Player 前端 (nginx)
  
  media-engine:    # 媒体引擎 (FFmpeg + 扫描)
    volumes:
      - /volume1/media:/media
  
  downloader:      # 下载调度
    image: mediahub-downloader:latest
  
  qbittorrent:     # 实际下载客户端
    volumes:
      - /volume1/downloads:/downloads
  
  mediahub-tv:     # Android TV Player (可选, 装在电视上)
```

> Apple TV 端因为是 Apple 生态的应用商店分发，不在 NAS 容器里。

## 7. 工作量与决策点

### 7.1 工时对照

| 模块 | 工作量 | 难度 | 备注 |
|---|---|---|---|
| CMS Backend | 10-15 天 | ⭐⭐⭐ | 核心 |
| CMS Admin + 布局编辑器 | 10-15 天 | ⭐⭐⭐⭐ | UI/交互密集 |
| Media Engine | 5-8 天 | ⭐⭐ | 复用 FFmpeg |
| Downloader | 3-5 天 | ⭐⭐ | 调度层 |
| Web Player | 5-7 天 | ⭐⭐ | |
| Android TV | 10-15 天 | ⭐⭐⭐ | 焦点系统是坑 |
| **tvOS** | **15-20 天** | ⭐⭐⭐⭐⭐ | **最难，国行签名也烦** |
| **总计** | **60-90 天** | | |

### 7.2 关键决策点

需要你确认的几个方向性问题：

1. **是否需要硬件转码**
   - NAS CPU 强（i3 以上）：可软转 4K
   - 弱（J4025 / ARM）：只能直连 + 1080p 转码
   - 影响：Media Engine 实现复杂度

2. **下载源策略**
   - 公开 BT：开箱即用
   - PT 站：需要邀请码、Passkey，长期可用要养号
   - 决定 Downloader 的索引源配置

3. **多用户粒度**
   - 全家共享：最简单，1 个账号
   - 家庭多账号 + 独立推荐：需要 JWT + 偏好隔离
   - 家长模式 + 分级：再加一层内容过滤

4. **布局编辑器粒度**
   - MVP：横滑 + Banner + 手动选片 + 库筛选
   - 进阶：模板继承、AB 测试、动态布局（按观看时段变化）
   - 全功能：所见即所得、可编程数据源

5. **tvOS 优先级**
   - 如果家里主要是 Android TV / 普通电视，tvOS 可以放最后甚至砍掉
   - 投屏（AirPlay / Cast）也能部分替代 tvOS

6. **是否要对接外部账号体系**
   - 单点登录（OIDC/SAML）：给后续扩展留口
   - 纯本地：家庭场景够用

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| tmdb API 限速 | 刮削慢 | 本地缓存 + 队列 |
| FFmpeg 转码吃 CPU | 卡 | 内网直连优先，转码仅作兜底 |
| 国行 Apple TV 应用签名 | tvOS 上架难 | 用 AltStore 侧载 或 个人开发者账号 |
| 自研 BT 协议 | 难度大 | 不自研，用 qBittorrent 做下载内核 |
| 字幕源失效 | 字幕缺失 | 多源 fallback + 本地字幕优先 |
| 家庭网络环境 | 内网穿透 | Tailscale / ZeroTier 组网 |
